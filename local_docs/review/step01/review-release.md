# リリースプロセスレビュー

最終更新: 2025-12-25

## 対象範囲

- ブランチ運用、タグ付け、デプロイの自動化

## 強み

- 品質ゲートが整備され、手動リリースでも安全性が高い。

## 課題

- タグ/リリースノート方針が未定義。

## 推奨アクション（短期）

- バージョニングの方針化（SemVer）、CHANGELOG 整備。

## チェックリスト

- [ ] リリースノート作成手順
- [ ] バージョンタグの規約

## 詳細レビュー（Step01）

- ブランチ戦略: `main` 安定、`feature/*` 開発、`release/*`
  任意運用。CI 合格が merge 条件として妥当。
- バージョニング: SemVer（MAJOR.MINOR.PATCH）で破壊的変更/機能/修正を分類。
- CHANGELOG: リンク（PR/コミット）を含む要約を維持。自動生成ツール（`changesets`
  等）も検討可。
- タグ: `vX.Y.Z` 形式で GitHub
  Release に紐づけ、成果物（dist）やデプロイリンクを付与すると分かりやすい。
