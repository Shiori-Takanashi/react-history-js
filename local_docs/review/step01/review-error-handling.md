## 詳細レビュー（Step01）

### エラーハンドリング・安定性

- **現状**: ローカル品質ゲートにより不整合は最小化。UI 側は Error
  Boundary 未導入のため、今後の追加を推奨（ルート配下に境界を配置）。
  > 評価: ⭐⭐⭐⭐☆（CI/Huskyで堅実。UI側の境界追加推奨）

### パターン設計

- ルート境界: `Routes` 直下に大域的 Error
  Boundary を設置し、ページ全体の致命的エラーを捕捉。
- コンポーネント境界: 履歴リストなど個別領域に局所的境界を追加して、部分的な失敗を許容。
- フォールバック UI: シンプルな再試行ボタンと、ログ概要（開発時のみ）を表示。

### ネットワーク/外部I/O（将来）

- 非同期処理は `try/catch` + `AbortController` によりキャンセル可能化。
- エラー分類（ユーザ起因/ネットワーク/内部）でメッセージを最適化。

### ログ/可観測性との連携

- Error
  Boundary からカテゴリ/メッセージ/スタックを収集し、開発時はコンソール、本番は軽量ロガーへ送出（サンプリング）。

### ユーザ体験

- 非致命の失敗はトーストで通知、致命的失敗はフォールバック画面。
- 重複抑止など期待された失敗は、短い説明と修正の一手を提示。
