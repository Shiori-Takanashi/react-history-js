# データ永続化レビュー

最終更新: 2025-12-24

## 詳細レビュー（Step01）

### データ永続化

- **現状**: セッションのみ（リロードで消える）。
- **提案**: オプション設定で `localStorage`
  保存を選択可能にし、履歴のエクスポート/クリア機能を UI に追加（[src/utils/historyStorage.js](../../../../src/utils/historyStorage.js)）。
  > 評価: ⭐⭐⭐☆（要件次第で拡張。現状は軽量志向）

### 設計オプション

- セッション保存（既存）: 軽量で副作用が少ないが、再訪問時に履歴が失われる。
- `localStorage`
  永続化: オフライン対応/再訪問の利便性。サイズ上限とシリアライズに留意。
- IndexedDB（将来）: 大量データ/複雑検索向け。導入コスト高だが柔軟。

### API 設計案（UI/Provider 側）

- `HistoryProvider` に保存戦略 `storageStrategy: 'session' | 'local'` を渡す。
- フック群にエクスポート/インポート/クリアの操作を追加（例:
  `useExportHistory()`, `useClearHistory()`）。
- ストレージ更新はデバウンス（100-300ms）で I/O 負荷を軽減。

### データ構造

- エントリ: `{ path, title, timestamp }` を基本とし、将来的に
  `meta`（クエリ/ラベル）を拡張可能に設計。
- 重複抑止: `Set`/`DuplicateChecker` を活用し O(1) 判定を維持。

### 同期／競合対策

- 複数タブ: `storage` イベントで他タブ更新を検知し、UI に反映。
- 破損対策: JSON 例外時にフォールバック（セーフティクリア + バックアップ復元）。

### UI への反映

- 設定トグル（セッション/ローカル）を `Header` か設定ページへ配置。
- エクスポート（JSON）/インポート（ファイル選択）/全部削除ボタンを履歴ビューに追加。

### テスト観点

- ストレージ書き込み/読み込みのユニットテスト。
- 重複抑止と保存の相互作用（同一パス連続）の E2E。
