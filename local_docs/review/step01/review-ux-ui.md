## 詳細レビュー（Step01）

### 情報設計 / レイアウト

- 100vh レイアウトで主要領域が明確。`Header`/`Footer`/`main`
  のランドマークを明示し、スクリーンリーダーでも把握しやすくする（[src/components/Header.jsx](src/components/Header.jsx)、[src/app/App.jsx](src/app/App.jsx)）。
- 履歴リストは縦スクロール前提。ページが長大化する前に仮想リスト導入（UXとパフォーマンスの両立）。

### インタラクション / ナビゲーション

- キーボードショートカットの設計（例: `/` で検索フォーカス、`j/k`
  で履歴上下移動、`Enter` で遷移）。導入時は `aria-keyshortcuts`
  を補助的に使用。
- ルート遷移時のフォーカス管理（`main` に `tabIndex=-1` +
  `focus()`）でアクセシブルなナビゲーションを担保。

### 検索 / フィルタ / 並び替え

- クライアントサイドの簡易フィルタ（文字列一致/前方一致）から開始。件数増加時は
  `fuse.js` のような軽量ファジー検索も検討。
- 並び替え（最新/古い順）とグループ化（ページ種別など）で閲覧性を向上。

### 空状態 / エンプティステート

- 履歴が空の際のガイド文とショートカット表示を用意。操作の次の一手を示すと UX が向上。

### マイクロコピー / フィードバック

- 追加/重複抑止時のトースト（非侵入型通知）と、画面内のインラインフィードバックのバランスを検討。
- 失敗時は原因と対処を短く表示（例: 「重複のため追加されませんでした」）。

### レスポンシブ / テーマ

- 最小ブレークポイント（320px/375px）でのレイアウト崩れ確認。CSS 変数で色/スペーシングを制御し、将来のテーマ切替に備える。

### 行動計測（UX 観点）

- 滞在時間、履歴追加頻度、検索使用率の簡易メトリクスを採取して改善に活用（オプション）。

### 推奨アクション（まとめ）

- 検索入力 + ショートカット `/` 導入、履歴リストへ仮想リスト検討。
- フォーカス管理/ランドマーク明示、空状態メッセージ追加。
- CSS 変数導入でスペーシング/カラーを整理。
